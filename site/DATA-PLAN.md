## Tested sources
### RDAP domain lookup (rdap.org, redirects to the registry RDAP server)
**Used by**: checkLink action — domain age signal
**Test command**: `curl -sL 'https://rdap.org/domain/solbarn.cc'` and `curl -s 'https://rdap.verisign.com/com/v1/domain/google.com'`, plus the same fetch through the ctx probe runner
**Sample output**: solbarn.cc -> events: registration 2026-11-04T13:49:01Z, expiration 2027-11-04, registrar NICENIC INTERNATIONAL GROUP CO., LIMITED (domain was 3 days old at the time of the drain). google.com -> registration 1997-09-15T04:00:00Z.
**Processing**: parse `events[]` for eventAction=registration, compute age in days at check time; <30 days = high-risk signal, 30-180 = caution, >180 = lower risk. Registrar name shown from entities[]. If RDAP 404s/errors, the signal is reported as 'tidak diketahui', never guessed.

### Target page fetch + static signal scan (server-side fetch of the user-pasted URL)
**Used by**: checkLink action — wallet-connect, contract, bait-language, obfuscation, social-link signals
**Test command**: `curl -sL -A 'Mozilla/5.0' 'https://scamsem.solbarn.cc/'` and the ctx probe (`bun /opt/muse/assets/spaces/ts-runtime/dist/probe-ctx.js < /tmp/probe-fetch.ts`)
**Sample output**: HTTP 200, 13,252 bytes HTML. Probe found: `window.TOKEN_ADDRESS` present, Solana addresses `41WpXn15fxQXEGhiKnkqHcoJn14tNXXgmymLKE57pump` (the exact mint drained from the user's wallet) and `BfJEEokcbSugKSjxEpgnAK1GU14jAM6c4Bvx1Gku1dFP`, `atob(` obfuscated click handler present, title `scamsem Airdrop`, airdrop claim copy in body.
**Processing**: fetch with redirect following (record final URL + cross-domain redirect), cap body size, scan HTML plus up to 3 same-origin script files for: EVM addresses (0x{40}), Solana base58 addresses, wallet-connect patterns (`connect wallet`, window.solana/ethereum, signTransaction, WalletConnect), claim/airdrop bait phrases, atob/eval obfuscation, presence of X/Telegram/social links, HTTPS. Each signal contributes to a transparent score; the verdict (BAHAYA / WASPADA / LEBIH AMAN) and every signal are shown individually so the user sees the evidence, not just a color.

## Long-term data behavior
- **Refresh policy**: no scheduled refresh; each check is an on-demand live fetch at the moment the user pastes a link. Re-checking the same link from history runs a fresh scan and saves a new row.
- **Growth**: one `checks` row per scan (URL, domain, verdict, score, signal list as JSON, domain registration date, checked-at). History list grows with use; user can delete individual rows.
- **Ordering**: history newest first.
- **Time semantics**: checked-at stored as creation instant, rendered viewer-local (Asia/Jakarta); domain age computed against the check instant.

## Rejected approaches
- **crt.sh certificate history as domain-age proxy**: `curl 'https://crt.sh/?q=solbarn.cc&output=json'` did not return within 20s (backgrounded, too slow/unreliable) — RDAP gives the true registration date directly, so crt.sh was dropped.
- **Google Safe Browsing / PhishTank / URLhaus blocklist APIs**: all require API keys/auth not available here; replaced with transparent on-page heuristics + RDAP + the user's own confirmed-bad domains from the incident.
- **Headless-browser rendering of the target page**: static fetch + script scan catches the signals the request asks for (contract, connect-wallet code, bait copy) without executing untrusted JS; rendering arbitrary scam pages server-side is slower and riskier.

Imagery not needed: the artifact is a verdict-first security tool; its visual language is the red/amber/green verdict and signal evidence, and the request names no visual subjects.

## addProject action: automated catalog intake (2026-11-07 edit)

- Rules enforced inside the action (returns `{ added: false, reason }` rather than throwing, so the scheduler can log rejections): duplicate project name (case-insensitive) or duplicate contract address → reject; missing/invalid official URL → reject; `contractBased: true` without an address, or any address failing EVM (`0x` + 40 hex, non-zero) / Solana base58 (32–44) format → reject; malformed `verifiedAt` (must be YYYY-MM-DD) → reject.
- On success: row is inserted with `sort` = current max + 1 (appended after the last project), explorer URL derived deterministically from chain + address (BscScan/Etherscan/Solscan), X handle normalized to `@handle`, and `listProjects` surfaces it with the default tracking state `task_status = not_started`, `bookmarked = false` (no `saved_projects` row is created). The 12 seeded catalog rows and all existing features are untouched; no schema change was needed.

## Persistence fix: catalog seed moved into a migration (2026-11-07 edit)

- Problem: the 12-project catalog was only seeded at runtime by `listProjects` (insert-when-empty), which had only ever run inside the audit sandbox — the durable `app.db` stayed empty (`projects: 0, saved_projects: 0`), so Explore / Featured / Upcoming and the dashboard would render empty in the shipped artifact.
- Fix: migration `drizzle/0004_seed_projects_catalog_permanently.sql` inserts the same 12 verified catalog rows (identical field values to the former runtime `CATALOG`) into `projects` at deploy time. Each insert is guarded by `WHERE NOT EXISTS` on the project name, so the migration is idempotent and cannot duplicate rows if the runtime fallback already seeded a database. Verified standalone: applied to an empty schema it yields exactly 12 rows (ids/sort 1–12, 5 live / 1 upcoming / 6 ended), apostrophes and quotes round-trip intact, and a re-run still yields 12.
- The runtime insert-when-empty fallback in `listProjects` is unchanged and now normally never fires; `saved_projects` (bookmarks + task status) persists per user via `setProjectState` as before — no saved state existed in durable storage to carry over (it was 0 rows).
